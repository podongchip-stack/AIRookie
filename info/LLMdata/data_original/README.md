# 원본 서류 (합성본)

이 브랜치의 서류 처리 성능을 확인할 때 쓰는 입력이다. 실측([`README.md`](../../README.md)의
"필드 추출 실측" 참고)은 54건(PDF 39 · PNG 15)으로 돌렸지만, 저장소 용량을 줄이려고
**여기에는 PDF 5건만 커밋한다.** 나머지는 필요할 때 팀 내부 경로로 받는다.

## 왜 이 폴더만 커밋하는가

같은 저장소의 `raw/`·`llm_raw/`·`ocr/output/`은 전부 커밋하지 않는다. 실제 병원
서류에서 읽어낸 내용이 들어갈 수 있어서다. 그런데 여기만 예외인 이유는 **이
서류들이 전부 합성본**이기 때문이다.

- 기관명이 실재하지 않는다 — `부산해솔종합병원`, `대전새길의료원`,
  `제주바람종합병원`, `한빛대학교병원` …
- 개인정보 자리는 더미값이다 — `970101-1234567`, `010-1234-5678`, `홍길동`
- 실제 환자·의료진의 정보가 들어 있지 않다

덕분에 팀원 누구나 받아서 바로 돌려볼 수 있다. **실물 서류를 여기 넣지 마라.**
넣어야 한다면 이 폴더를 커밋 대상에서 빼는 것이 먼저다.

## 쓰는 법

```bat
python simulation\gui.py
```

창에 이 폴더의 파일을 **전부 끌어놓으면** 순서대로 처리된다. 하나씩 넣을 필요 없다.
성능만 확인할 거라면 설정은 기본값 그대로 두면 된다 — 학습 데이터는 쌓이지 않고
추출 결과만 `ocr/output/`에 남는다 ([`simulation/README.md`](../../simulation/README.md)).

CLI(`run_extract.py --image`)는 이미지만 받고 PDF는 못 받는다. 지금 이 폴더에는
PDF만 있으므로 CLI로 돌리려면 PNG 등 이미지를 따로 넣어야 한다 —
`simulation/gui.py`를 쓰는 편이 더 간단하다.

## 주의

여기 커밋된 5건은 약 1.4MB다. 서류를 더 넣을 때는 저장소가 그만큼 무거워지고
**한 번 커밋하면 나중에 지워도 히스토리에 남는다**는 점을 감안할 것.
