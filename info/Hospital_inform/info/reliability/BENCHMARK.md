# 병상 정보 신뢰도 모델 — 왜 XGBoost AFT인가, 그리고 벤치마크

> 작성 2026-10-07 · 대상 모델: E-Gen 응급실 일반병상(hvec) 신뢰도 생존모델 `aft_egen_theta3_ext0923`
> 재현: `cd info/Hospital_inform/info && python -m reliability.benchmark_deep` (스크립트 `reliability/benchmark_deep.py`)
> 결과 원본: `data/benchmark/benchmark_hvec_theta3.json`(시드별 값) · `.md`(요약표)

## 1. 한 줄 결론

같은 데이터·같은 분할·같은 지표로 비교했을 때 **딥러닝 생존모델(DeepSurv·DeepHit)은 순위 예측에서 의미 있는
이득이 없었고, 우리가 실제로 쓰는 "몇 % 확률" 숫자는 오히려 덜 정확했다.** 서빙 중인 XGBoost AFT(+잔차 재보정)를
그대로 쓰는 것이 맞다.

## 2. 이 모델이 하는 일

- E-Gen이 주는 병상 수는 병원이 스스로 신고한 값이고, 언제까지 맞을지는 알려주지 않는다.
- 모델은 병원·시점마다 "지금 보이는 병상 숫자가 **지금 / 구급차 도착 시점에도** 유효할 확률"을 낸다.
- 단위: 병원의 병상 값이 바뀔 때마다 새 "버전"이 태어난다. 다음 변화가 **3석 이상**이면 그 버전은 무효(사건),
  3석 미만 잔변화·관측 공백·데이터 끝은 검열.
- 사건 시각은 정확히 모른다 — E-Gen을 20분마다 조회하므로 "마지막으로 같은 값을 본 때 ~ 바뀐 값을 처음 본 때"
  사이 어딘가다(**구간검열**). 끝까지 안 바뀐 버전은 "최소 이만큼은 버팀"(**우측검열**).
- 피처는 병상 숫자의 내용이 아니라 **갱신 행동** 9종이다(버전 번호, 이전 수명, 평균 갱신 간격, 변화폭, 시각·요일,
  병원의 평소 버전 수명 등).

## 3. 왜 XGBoost AFT인가

### 3-1. 핵심: 우리 라벨(구간검열)을 그대로 학습할 수 있는 트리 모델이 드물다

XGBoost는 생존분석 손실 `survival:aft`를 내장하고, 라벨을 하한·상한 두 값으로 받아 구간검열과 우측검열을 손실 함수에서
그대로 처리한다.

| 트리 계열 | 생존분석 지원 | 구간검열 |
|---|---|---|
| **XGBoost** | AFT 손실 내장(`survival:aft`), Cox 손실(`survival:cox`)도 있음 | **됨** |
| LightGBM | 생존분석 손실 없음 | 안 됨 |
| CatBoost | AFT 손실(`SurvivalAft`) 있음 | 지원하는 것으로 알려져 있으나 **우리 데이터로 검증 안 함** |
| scikit-survival 부스팅 | Cox 등 | 우측검열만 |
| 랜덤 생존 포레스트(RSF) | 됨 | 우측검열만 · 우리 규모에서 너무 느림 |

이번 벤치마크도 이를 뒷받침한다 — 같은 XGBoost AFT에 구간을 버리고 "한 시점" 라벨을 주면 30분 확률 오차(ECE)가
**0.100 → 0.163**으로 크게 나빠졌다(§6).

### 3-2. 결과가 수식으로 나온다

AFT는 병원마다 "예측 생존시간" m 하나를 내고, 생존곡선은 로그정규 공식으로 정해진다.

```
S(t)        = 1 − Φ((ln t − ln m) / σ)
지금 유효    = S(나이)
도착 시 유효 = S(나이 + 도착까지 시간)
재확인 시점  = authority가 0.8 아래로 떨어질 때까지 남은 시간(해석해)
병원 확인 뒤 = S(나이) / S(확인 시점 나이)
```

hub는 모델 파일 없이 숫자 몇 개(m, 탄생 시각, σ)만 받아 표준 라이브러리로 매칭 시점마다 다시 계산한다.
곡선을 표로 내는 모델(RSF, DeepHit 등)이나 기준 위험 표가 필요한 모델(Cox, DeepSurv)은 이렇게 가볍게 운영할 수 없다.

### 3-3. 운영 조건에 맞다

- **결측값을 그대로 받는다** — 첫 버전은 "직전 수명" 같은 피처가 원래 비어 있는데, 채우지 않고 학습한다.
- **가볍다** — CPU 수 분 학습(벤치마크에선 0.3초), 모델 파일 수 MB, GPU·클라우드 불필요. 전국 1개 모델로 충분하고
  신규 병원에도 그대로 적용된다(zero-shot이 native의 99%).
- **피처 검증** — 모델 파일에 피처 이름이 저장돼, 서빙이 불러올 때 정의가 어긋나면 그 자리에서 실패시킨다.

### 3-4. 연구 단계에서 실제로 비교한 기록

- **Cox PH**: 심각한 어긋남 영역에서 C-index **0.284로 역방향 붕괴**(선형·비례위험 가정이 비단조 구조를 못 담음).
- **RSF**: 15만 행에 **55분 이상** — 규모에서 탈락.
- **필수 대조군**: "평소 갱신 간격만 쓴 모델"(INTERVAL)을 매번 이겨야 모델로 인정.

> ⚠ CatBoost AFT·LightGBM 등 다른 트리 라이브러리와 **성능을 직접 겨룬 기록은 없다.** 선택은 "구간검열을 직접 받는
> 트리 모델"이라는 기능 조건과 위 비교에 근거한다.

## 4. 비교 대상 — DeepSurv·DeepHit는 무엇이고 왜 골랐나

| | DeepSurv (Katzman 외, 2018) | DeepHit (Lee 외, 2018) |
|---|---|---|
| 개념 | Cox 모델의 선형 부분을 신경망으로 바꾼 것 | 시간을 구간으로 나눠 구간별 사건 확률을 신경망이 직접 예측 |
| 가정 | **비례위험**(대상 간 위험 차이가 시간 내내 일정) | 가정 없음, 경쟁위험 처리 가능 |
| 출력 | 위험 점수(생존곡선은 기준 위험 추정이 추가로 필요) | 구간별 생존곡선 |
| 손실 | Cox 부분우도 | 우도 + 순위 손실 |
| 검열 | 우측검열만 | 기본은 우측검열 |

- **고른 이유**: 딥러닝 생존분석에서 가장 많이 인용되는 대표 모델이고, 서로 다른 두 계열(연속시간·비례위험 /
  이산시간·가정 없음)을 하나씩 대표한다. 새 생존모델 논문의 비교 기준으로 거의 빠지지 않는다.
- **덧붙인 비교군**: Cox PH(선형, DeepSurv에서 신경망을 뺀 원형) · INTERVAL(필수 대조군) · 점 라벨 AFT(라벨 방식 차이
  분리) · AFT+재보정(실제 서빙과 같은 형태).
- **이번에 비교하지 않은 모델**(추가 후보):

| 모델 | 계열 | 비교하면 알 수 있는 것 |
|---|---|---|
| XGBoost Cox(`survival:cox`) | 트리 + 비례위험 | 차이가 "트리 vs 신경망"인지 "AFT vs Cox"인지 분리 |
| CatBoost AFT | 트리 + AFT | 같은 기능의 다른 트리 라이브러리와 성능 비교 |
| AFT 분포 변경(로지스틱·극값) | 트리 + AFT | 이번에 약했던 곡선 전체 정직성(D-cal)이 분포 탓인지 |
| RSF(표본 축소) | 트리 앙상블 | 연구 단계 탈락 이유를 수치로 |
| Logistic-Hazard / N-MTLR | 이산시간 신경망 | DeepHit보다 확률이 정직한 편으로 알려진 모델 |
| Cox-Time | 비례위험을 푼 신경망 Cox | DeepSurv의 가정 한계 |
| Weibull 등 모수 모델 | 고전 통계 | 가장 단순한 기준선 |

### 지표

| 지표 | 뜻 | 좋은 방향 |

## 7. 해석

1. **순위 예측은 사실상 비슷하다.** DeepSurv(0.7394)가 XGB-AFT(0.7367)보다 0.003 높지만 시드 간 흔들림(약 0.002)
   수준이다. DeepHit는 같거나 낮다. 모든 모델이 리듬만 쓴 모델(0.686)보다는 확실히 높다 — 행동 피처가 실제로 효과가 있다.
2. **실제로 쓰는 확률 숫자는 서빙 방식이 가장 정확하다.** 화면의 "도착 시점에도 유효할 확률"과 같은 종류의 숫자를 보는
   30분 확률 오차가 XGB-AFT+재보정에서 0.093으로 가장 낮다. DeepSurv 0.130, Cox 0.132, DeepHit 0.114~0.144.
3. **구간검열을 직접 받는 것이 확률 정확도에 중요하다.** 점 라벨로 바꾼 AFT는 순위가 조금 오르지만(0.742) 30분 확률
   오차가 0.100 → 0.163으로 나빠진다.
4. **DeepHit는 원 논문 설정에서 확률이 많이 틀린다.** α=0.2(순위 손실 섞음)는 IBS·ECE·D-cal 모두 최하위 — 순위 손실이
   확률을 왜곡한다는 알려진 성질과 맞다. 우도만 쓰면(α=1) 크게 나아진다.
5. **신경망이 나았던 부분**: 곡선 전체의 정직성(D-cal)은 DeepSurv·Cox(0.0002)가 AFT(0.0033)보다 좋다. AFT는 곡선 모양을
   "로그정규, σ 고정"으로 두어 아주 짧거나 긴 시간대에서 어긋날 수 있다는 뜻이다 → 병원별 σ, 다른 분포 시험이 개선 후보.
6. **결론**: 딥러닝 모델은 의미 있는 이득이 없고, 쓰는 확률은 덜 정확하며 운영은 더 무겁다(기준 위험 표·구간 표 필요).
   XGBoost AFT + 잔차 재보정을 유지한다.

## 8. 한계 (발표·보고 시 함께 밝힐 것)

- **조정 안 함**: 신경망은 표준 설정 그대로다(하이퍼파라미터 탐색 없음). XGBoost도 서빙 설정 그대로. 조정하면 차이가 줄 수 있다.
- **직접 구현**: DeepSurv·DeepHit는 Mac GPU에서 돌리려고 PyTorch로 직접 구현했다. 손실식은 표준 구현(pycox)과 같지만
  pycox 자체는 아니다. 사전 시험에서 찾은 구현 버그 2건(시간의존 C를 사건 직전 격자에서 계산해 동점이 생기던 것,
  DeepHit 구간 경계에서 사건을 한 칸 늦게 배정하던 것 — 20분 폴링이라 사건 시각이 경계와 정확히 겹친다)을 고친 뒤 돌렸다.
- **기간 효과**: 시험 기간(09-22 ~ 10-06)에 주말이 들어 있어 C가 문서 기록(θ3 0.764, 16일 모델·다른 기간)보다 낮다.
  같은 기간 안에서만 비교해야 한다.
- **재보정 조건**: 여기선 검증 기간(학습 기간 끝 15%)으로 재보정했다. 실제 서빙은 학습 이후 기간으로 맞춘다.
- **XGBoost 조기 종료**: 이 벤치마크는 모든 모델을 검증 구간으로 조기 종료했다(약 40라운드에서 멈춤). 서빙 학습
  프로토콜은 시험 구간을 조기 종료에 겸용한다.
- **라벨 등급**: 라벨은 병원의 다음 자기 신고로 정해진다(G1). "병원이 실제로 받았는가"(G2)는 아직 평가하지 않았다.
