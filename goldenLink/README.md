# 골든링크 — 병원 매칭 대시보드 시스템

응급 이송 골든타임 단축을 위한 실시간 병원 매칭 로직 정리

> 팀 골든링크 · 2026 AI ROOKIE 대회

## 1. 배경 및 목적

골든타임 단축을 위해, 구급대원이 여러 병원에 순차적으로 전화를 돌리는 "뺑뺑이" 문제를 해결한다. 첫 병원과의 통화 내용을 텍스트로 요약(실시간 음성 필터링 처리)해서 모든 후보 병원에 동시에 전달하는 방식으로 순차 전화의 시간 낭비를 없앤다.

> 통화 음성 → 텍스트 요약 파이프라인은 [`voiceSummation`](./voiceSummation)에서 담당한다.

## 2. 전체 흐름

1. **정보 전달** — 구급차가 이송을 시작하면, 첫 병원과의 통화 음성을 텍스트로 요약해 존(Zone) 내 모든 병원에 일괄 전달한다. 구급차 대시보드에는 GPS 기준 가까운 순서로 병원 리스트가 시각화된다.
2. **병원 측 응답** — 병원은 대시보드에서 "병원 승인"(수용 가능) 또는 "불가"(수용 불가) 버튼으로 명시적으로 응답한다.
3. **구급대원 측 최종 결정** — 병원이 "병원 승인"을 누르면, 해당 병원이 구급차 대시보드에 "이송 승인" 가능 대상으로 표시된다. 2개 이상의 병원이 동시에 승인해도 문제없이 모두 표시되며, 구급대원이 그중 하나를 골라 "이송 승인" 버튼을 눌러 확정한다.
4. **이동 중 재선택 가능** — 이미 특정 병원으로 이송을 시작한 이후에도, 새로운 병원이 뒤늦게 "병원 승인"을 누르면 구급차 대시보드에 팝업/모달로 알림이 뜨고 재선택이 가능하다. 다른 병원으로 최종 확정하면 기존에 승인했던 병원들에는 취소 알림이 가고 시스템에서 취소 처리된다.
5. **무응답 병원 처리 (존 자동 확장)** — 시간 기준이 아닌 명시적 거절 비율 기준으로 확장한다. 존 1의 병원 중 일정 비율 이상이 "불가"를 누르면, 존 1의 나머지 병원 응답은 계속 기다리는 동시에 존 2까지 자동으로 정보가 확장 전달된다.

## 3. 바이탈(생체정보) 전송 범위

이송 승인이 확정된 병원에만 실시간 바이탈이 전달된다. 이송 중 다른 병원으로 전환이 확정되면, 기존 병원으로의 바이탈 전달은 즉시 중단되고 새로 확정된 병원으로만 전달된다. 즉 항상 **하나의 확정 병원에만** 실시간 바이탈이 흐른다.

## 4. 대시보드 구성

| 구분 | 구성 요소 |
|---|---|
| **구급차 측**<br>(운전대원 / 구급대원용) | 첫 병원과의 전화 원본 내용 / 요약 내용<br>존 내 병원들의 GPS 기준 거리순 리스트<br>지도·내비게이션, 병원별 승인 여부 표시, 최종 승인(이송 승인) 버튼<br>구급차 내부 부상자 바이탈 |
| **병원 측** | 첫 병원과의 전화 원본 내용 / 요약 내용<br>지도·내비게이션 (구급차 현재 위치, 도착 예상 시간), 병원 승인 / 불가 버튼<br>구급차 내부 부상자 바이탈 (이송 승인된 병원에만 표시) |

## 5. 아직 확정되지 않은 부분

- **존(Zone) 거리 기준**: 아직 미정
- **존 확장 트리거 비율**: 존 1 내 "불가" 응답이 몇 % 이상일 때 존 2를 여는지 구체적 수치 미정
- **"불가" 버튼 UI 반영**: 기존 병원 측 대시보드 초안에는 "승인" 버튼만 있었으나, 본 정리안에서 "불가" 버튼을 추가로 반영함

## 참고 — 이동 중 병원 전환 시 유의사항

이미 A병원 방향으로 이동 중 다른 병원으로 전환할 경우, 물리적으로 이동 경로가 역행할 수 있다. 전환 시 남은 예상 이동 시간을 비교해 실제로 더 빠른 경우에만 전환하도록 안내하는 것을 권장한다.
