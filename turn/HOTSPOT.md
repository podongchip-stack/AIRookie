# Mac 서버 + 모바일 데이터 두 기기

구성: Mac은 개인용 핫스팟, 두 휴대폰은 각각 구급대/병원 코드로 접속한다. iPhone/Android 조합은 자유다.
Mac에서 저장소 루트의 `./start-all.sh --hotspot`을 실행한다. 공유기 포트포워딩이나 로컬 TURN은 사용하지 않는다.
hub·dashboard·Cloudflare 공개 터널을 실행하며, 두 앱은 아래 주소에 연결한다.

```text
https://app.rookie-goldenlink.xyz
```

- 양쪽 앱의 서버 주소 설정을 확인한다. Mac의 `localhost`, 내부 IP, 핫스팟 IP를 넣지 않는다.
- 수신 기기에서 병원 코드 `H-<실제 hpid>`로 접속한 뒤 앱을 열어둔다.
- 발신 기기에서 구급대 코드 `P-<실제 apid>`로 접속하고 사건의 해당 병원을 선택해 발신한다.
- 수신 기기에서 받기를 누르고 양쪽 음성과 종료를 확인한다.
- 병원·구급차 코드는 공개 관제 지도 `/map`에서 실제 등록된 값을 확인한다.

Mac은 신호 중계 서버다. 실제 음성은 공개 STUN으로 주소를 찾은 두 앱이 직접 주고받는다.
웹 대시보드의 병원 화면은 이 네이티브 통화의 수신 기기가 아니다(iPhone/Android 앱 병원 모드를 사용).
통신사 NAT 때문에 직접 연결이 안 되면 이 구성에서는 음성이 연결되지 않을 수 있다. 공개 페이지와 WebSocket 성공이 음성 성공을 뜻하지 않는다.
푸시·잠금 화면 수신·STT 모델 통합은 이 서버 실행으로 검증되지 않는다.

Mac이 잠자기 상태에 들어가거나 핫스팟이 끊기면 서버 접속도 끊긴다. 네트워크를 바꾼 뒤 공개 주소가 다시 열리는지 확인하고,
복구되지 않으면 Ctrl-C 후 같은 명령으로 재실행한다. 로그는 `/tmp/goldenlink-logs/`.
