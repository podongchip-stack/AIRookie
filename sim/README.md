# 대량사고(MCI) 이송 시뮬레이션 — 순차 전화 vs 골든링크

> feature/sim 브랜치 (2026-10-03 신설). **기존 파일은 수정하지 않고 새 파일만 추가**하는
> 규칙으로 운영한다 — 결선 후 통째로 지워도 다른 브랜치에 영향이 없다.
> 목적: 발표 슬라이드의 "대량사고 대응"을 계획이 아니라 **수치로 검증된 결과**로 바꾸는 것.

## 무엇을 비교하나

이태원 참사(2022-10-29 22:15)와 같은 조건 — 같은 장소(이태원역), 같은 시간대의
**실제 E-Gen 병상 스냅샷**(이 저장소 수집기가 20분 주기로 찍은 원본) — 에서
사상자 N명을 세 가지 방식으로 분산 이송했을 때의 차이를 잰다.

| 팔(arm) | 뜻 | 현실 대응물 |
|---|---|---|
| `nearest` | **최근접 집중** — 병상 정보 없이 전원 가장 가까운 응급실로. 만실이면 도착 후 전원(재이송) | 이태원 당시 실제 상황 (순천향대병원 집중) |
| `sequential` | **순차 전화** — 가까운 순으로 전화(통화당 수 분), 자리 있는 곳에 예약 후 출발 | 평시 "뺑뺑이" 관행 |
| `goldenlink` | **동시 전달** — 존 후보 전체에 동시 요청(1회 비용), 가용 병원 중 최단 이동 병원 배정 + 예약. hub가 자기 배정을 전부 보므로(TTL 오버레이) 같은 병원에 몰아 보내지 않는다 | 골든링크 |

## 지표

1. **쏠림**: 병원별 `도착 환자 / 가용 병상` 최대값 (nearest에서 1을 크게 넘는다 —
   재이송·과밀의 직접 원인)
2. **최종 수용까지 시간**: 사상자별 "현장 출발 대기 시작 → 최종 수용 병원 도착"의
   중앙값·p90 (재이송 시간 포함 — 골든타임 지표)
3. 보조: 재이송(전원) 건수, 거절 전화 수, 전체 종료 시각

## 데이터 (전부 이 저장소 안의 실측)

- **병원 위치**: `info/Hospital_inform/info/data/output/<hpid>.json` (E-Gen 좌표,
  서울 55곳) — 좌표는 변하지 않으므로 8월 캐시 그대로 사용
- **가용 병상**: `info/Hospital_inform/info/data/snapshots_nationwide/<날짜>.jsonl`
  의 `getEmrrmRltmUsefulSckbdInfoInqire` 기록 중 목표 시각(기본 22:15)에 가장
  가까운 것. `hvec` 음수는 과밀(가용 0)로 읽는다(2026-10-01 합의와 동일),
  `hvec` 없는 병원은 미상이라 제외
- 기본 장면: 이태원역(37.53465, 126.99418) 반경 10km — 실측 33곳

## 모델 가정 (전부 파라미터, `run.py --help`)

- 구급차 M대(기본 30)가 현장↔병원을 왕복한다. 중증(immediate) 환자부터 싣는다
- 이동: 직선거리 × 도로우회율 1.3, 시속 40km (심야 서울)
- 시간 비용: 적재 3분, 인계 8분, **전화 1통 2.5분**(sequential), **동시 요청 1분**
  (goldenlink), 재이송 추가 인계 5분
- 병원 수용: 자기 상태(수용+예약)를 아는 병원만 승인한다 — sequential/goldenlink는
  예약이 성립하므로 도착 거절이 없고, nearest는 도착 후에야 만실을 안다
- 사상자 중증도: immediate/urgent/delayed = 30/40/30% (파라미터) — v1에서는
  분류(이송 순서)에만 쓴다

### 상수의 근거 — "그 숫자 어디서 났나"에 대한 답

핵심 방어선부터: **세 팔에 똑같이 들어가는 상수(적재·인계·이동속도·도로보정)는
비교 결과의 원인이 될 수 없다** — 어느 값을 쓰든 세 팔에 같은 양이 더해진다.
팔 사이 차이를 만드는 건 ① 결정 시간(전화 vs 동시 요청)과 ② 배정 방식(쏠림·재이송)
뿐이고, 이 둘은 `--sweep` 민감도로 흔들어 순서 불변을 확인한다.

| 상수 | 값 | 성격 | 근거 |
|---|---|---|---|
| 이동 속도 | 40km/h | 공통(결과 무관) | 심야 서울 간선도로 수준. 주간이면 느려지지만 세 팔이 같이 느려진다 |
| 도로 우회율 | 1.3 | 공통(결과 무관) | 도시 도로망의 통상 우회계수 1.2~1.4의 중간값 |
| 적재 / 인계 | 3분 / 8분 | 공통(결과 무관) | 팀 가정 — 값 자체는 비교에 영향 없음 |
| **전화 1통** | **2.5분** | **차이 유발 — 민감도 필수** | 팀 가정(연결 대기+환자 요약+응답). `--sweep`이 1.5~4분을 흔듦 — 전 구간에서 순서 불변, sequential 중앙값만 23~37분으로 움직임 |
| **동시 요청** | **1분** | **차이 유발** | 통화 종료 후 전송~병원 응답까지의 여유 가정 (실측 구조화 지연은 3.7초 — 1분은 병원 응답 대기를 포함한 보수적 값) |
| 재이송 추가 | 5분 | nearest에만 | 팀 가정 — nearest에 불리하지 않게 짧게 잡음(보수적) |
| 중증도 분포 | 30/40/30 | 순서에만 영향 | MCI triage 통상 분포 가정. 수용 시간·쏠림 지표에는 영향 없음 |

보수성 원칙: 모호하면 **베이스라인에 유리한 쪽**을 골랐다 — 구급차별 만실 기억
반영, 재이송 비용 최소화, 정보 무효율 0. 그래도 격차가 나는 것이 이 결과의 힘이다.

## 정직한 한계 (발표에서 먼저 말할 것)

- **시간 비용 상수(전화 2.5분 등)는 가정**이다 — 민감도(`--sweep`)로 상수를
  흔들어도 결론 방향이 유지됨을 함께 제시한다
- 세 팔 모두 같은 구급차 수·같은 환자·같은 병상에서 출발한다 — 차이는 순수하게
  **정보 전달 방식**에서만 나온다
- 병원의 실제 수용 능력(병상 외 인력·수술실)은 모델에 없다. E-Gen `hvec` 하나로
  단순화했다 — 실제 수용 가능성은 이보다 복잡하다
- 신고 정보가 처음부터 틀렸을 가능성(정보 무효)은 v1에서 0으로 둔다 —
  v2에서 infosurv 생존확률을 거절 확률로 주입하는 자리(`info_error_rate`)만 파 둠
- 사상자 수·중증도 분포는 보도 기준 가정이며 슬라이더로 바꿔볼 수 있다

## 실행

```bash
# conda activate rookie_info (stdlib만 쓰지만 이 환경이 확실)
cd sim
python run.py                       # 기본: 환자 120, 구급차 30, 시드 20개
python run.py --patients 150 --seeds 30
python run.py --sweep               # 상수 민감도(전화 시간·환자 수) 표
python make_slides.py               # 발표용 1920×1080 PNG 2장 (slide_summary, slide_hospitals)
# 결과: sim/out/results.json + sim/out/mci_report.html (자가완결 — 그냥 브라우저로 열면 됨)
```

리포트의 재생 화면은 구급차 점이 실시간으로 움직인다(빨간 테두리 = 재이송 중,
흐린 점 = 복귀). `mci_report.html#t=30&arm=nearest`처럼 해시로 특정 장면을
바로 열 수 있다 — 시연 중 "30분 시점의 최근접 집중" 같은 장면 점프용.
