# simulation3 — STT 오인식 교정 필터

whisper가 뱉은 텍스트에 **따로 필터를 돌려** 오인식을 고치고, 그 결과를 LLM에 넘긴다.
whisper 자체에는 아무것도 붙이지 않는다.

```
음성 파일
   │ faster-whisper (GPU 자동/CPU 폴백)
   ▼
텍스트 ──▶ 오인식 교정 필터 (corrections.json, 정확 일치)
   ▼
교정된 텍스트 ──▶ Ollama LLM 2회 호출
   │                ├─ SBAR 구조화 (팀과 동일 프롬프트)
   ▼                └─ 환자 상태 1~2문장 요약
CallSummaryMessage 형태 JSON + patient_brief (화면 표시 / 파일 저장)
```

이 폴더는 자립형이다. 실행과 점검에 필요한 것이 전부 안에 있다.

## 교정 방식 — 정확히 일치할 때만 바꾼다

`corrections.json`에 등록된 "오인식 → 정답" 쌍과 **정확히 일치**하는 구간만 치환한다.
등록하지 않은 말은 절대 건드리지 않으므로 **오교정이 구조적으로 발생할 수 없다.**
유사도 임계값 같은 튜닝 대상도 없다.

대신 **등록한 만큼만 잡힌다.** 통화 녹음에서 오인식을 발견할 때마다 `corrections.json`에
한 줄씩 추가하는 것이 이 방식의 운영법이고, 제대로 추가하면 교정 건수가 그만큼 늘어난다.

정확 일치를 보되, 실제 문장에서 걸리게 하려고 세 가지는 처리한다.

1. **조사 분리** — 실측 오인식이 `"재세동이"`였다. 조사 `"이"`를 떼야 사전의 `"재세동"`에
   걸리고, 치환 후 다시 붙여 `"제세동이"`가 된다. 그래서 사전에는 조사를 뺀 형태로 적는다.
2. **공백 정규화** — whisper가 `"번지 회"`처럼 띄어 쓸 수 있어 1~3어절 구간을 붙여서
   조회한다. 사전 쪽 표기도 같은 방식으로 공백을 빼고 맞추므로, 사전에 띄어 적든
   붙여 적든 상관없다.
3. **긴 구간 우선** — 겹치는 자리는 더 긴 구간이 가져간다.

### 실측 결과

실제 전화 통화 녹음 5건을 whisper로 전사하고, 그 대본(정답)과 대조해 오인식을 뽑아
사전에 등록했다. 같은 데이터로 측정한 효과:

| 모델 | 교정 건수 | 정답과의 유사도 |
|---|---|---|
| small | 31건 | 86.24% → **88.32%** (+2.08%p) |
| medium | 15건 | 88.67% → **90.24%** (+1.56%p) |
| large-v3 | 16건 | 88.92% → **89.68%** (+0.76%p) |

같은 사전을 정답 대본에 돌리면 **교정 0건**이다 — 정상 발화는 건드리지 않는다.

사전을 162개로 늘린 뒤 실측 텍스트 45건(녹음 5 × 디코딩 설정 9종)에 적용한 결과:
**교정 161건, 정답에 가까워진 텍스트 28건, 멀어진 텍스트 0건.**

잡히는 예:

```
짐근 경색을    -> 심근경색을        한은고제의   -> 항응고제의
협신증이나     -> 협심증이나         영상의약과   -> 영상의학과
의식콘탁속연이고요 -> 의식혼탁 소견이고요   내 추렬을    -> 뇌출혈을
반신 불안전 마비속연이고 -> 반신불완전마비 소견이고
```

`"1흔대"`(← 70대), `"번지회"`(← 2회) 같은 숫자·나이 오인식도 등록만 하면 잡힌다.
유사도 기반 방식으로는 원리상 불가능했던 것들이다.

## 실행 (Anaconda Prompt)

사전 조건: **Ollama 앱 켜기** (요약 LLM용)

```bat
conda activate AIRookieProject
```

[진행 로그 / STT 원문 / 교정 결과 / SBAR 요약] 확인 → 필요 시 JSON 저장.

**환자 상태 요약**은 탭 위 고정 칸에 항상 표시된다. **시스템 프롬프트** 탭에서 SBAR
프롬프트를 고쳐 실행하면 그 실행에만 반영된다 (`기본값 복원`으로 되돌린다).

## 오인식 사전 (`corrections.json`)

```json
{
  "corrections": {
    "재세동": "제세동",
    "번지회": "2회",
    "1흔대": "70대"
  }
}
```

왼쪽이 whisper가 잘못 뱉는 표기, 오른쪽이 정답이다.

### 적는 규칙

| 위치 | 규칙 |
|---|---|
| 왼쪽 | **띄어쓰기는 신경 안 써도 된다** — `"지혈 때"`와 `"지혈때"`가 같게 동작한다. STT 출력에서 그대로 복사해 붙여도 된다 |
| 왼쪽 | 2글자 이상 (1글자는 `"안"` 같은 흔한 말을 통째로 치환해 위험) |
| 왼쪽 | **조사·종결어미는 빼고** (`"재세동이"`·`"재세동입니다"` → `"재세동"`. 교정기가 붙여준다) |
| 왼쪽 | **정상 한국어 단어는 절대 금지** (아래 참고) |
| 오른쪽 | 제약 없음 — 공백·숫자·영문 다 가능 |

#### 왼쪽에 정상 단어를 넣으면 안 되는 이유

whisper가 `"수용"`을 `"수영"`으로 6번 틀렸다고 해서 `"수영" → "수용"`을 등록하면,
정상 발화가 파괴된다.

```
"수영 중에 다리에 쥐가 났다고 합니다"  ->  "수용 중에 다리에 쥐가 났다고 합니다"
```

두 어절을 붙여 비단어로 만들면 안전하다: `"수영가능" → "수용 가능"`.
`"앞면"`(정상 단어)은 안 되지만 `"앞면마비"`(비단어)는 되는 것과 같은 원리다.

#### 오른쪽 주의 — 받침이 바뀌면 조사가 어색해진다

교정기는 떼어낸 조사를 그대로 다시 붙인다. 그래서 오른쪽 끝 글자의 받침이 왼쪽과
달라지면 조사가 틀어진다.

```
"소개" -> "소견"  등록 시:  "소개는"  ->  "소견는"   (X, "소견은"이어야 함)
```

이런 경우는 등록하지 않는 편이 낫다.

### 고친 뒤에는 자체 점검을 돌린다

```bat
python text_postprocess.py
```

세 가지를 본다. 전부 코드 안에 들어 있어 별도 데이터 파일이 필요 없다.

- **형식 검사** — 공백 든 표기, 1글자 표기, 중복 항목, 오인식과 정답이 같은 항목.
  이 위반들은 실행 중에 에러를 내지 않고 **조용히 무시**되므로 눈으로는 알기 어렵다.
- **교정 동작** — 실측 STT 출력에서 조사 분리와 숫자 교정이 제대로 도는지.
- **무교정 확인** — 오인식이 없는 정상 통화 문장에서 교정이 **0건**인지.
  여기서 교정이 나오면 정상 단어를 오인식 표기로 잘못 등록했다는 뜻이다.

## 앞으로 — 오인식을 모으는 법

지금 등록된 건 6개뿐이다. 실제 통화 녹음이 쌓이면 이렇게 늘려간다.

1. 통화를 STT로 돌려 텍스트를 뽑는다
2. 정답과 대조해 틀린 표기를 찾는다
3. `corrections.json`에 `"틀린표기": "정답"` 한 줄 추가
4. `python text_postprocess.py`로 점검

숫자·나이·약어처럼 whisper가 반복해서 틀리는 것부터 넣으면 효과가 크다.
