# 휴대폰 사건 기록 동기화 (2026-11-01)

## 동작

hub의 `data/state/case_records.sqlite3`가 원본 저장소이고 휴대폰의 날짜별 파일은 오프라인 복사본이다.
구급차 ID(`apid`)별로 사건·인계확인서·수용 승인/거절·최종 이송 승인·수용 철회·도착 결과를 보관한다.
사건이 종료되거나 시연을 초기화해도 보관소의 기록은 지우지 않는다. 음성·통화 원문은 이 보관소에 넣지 않는다.
기존 `decision_log.py`의 해시 체인 로그도 그대로 유지한다.

- 최초 설치: 서버에 보관된 사건을 페이지별로 내려받는다(최대 100개 변경 사건/페이지).
- 기존 설치: 이 기기에만 있던 과거 기록을 최대 20개씩 이관한다. 이미 서버에 있는 사건은 덮어쓰지 않는다.
  이관 기록에는 `legacyImport=true`가 붙는다. 과거 응답 변경 이력이 없으면 이를 만들어 내지 않는다.
- 이후: 서버 변경 순번 이후 바뀐 사건만 받는다. 과거 사건도 수정되면 새 순번을 받으므로 누락되지 않는다.
  한 사건이 여러 번 바뀌었어도 페이지에는 최신 스냅샷 한 개만 포함된다.
- 승인했다가 거절한 과정은 `events[]`에 따로 남는다. 스냅샷의 현재 응답 상태와 구분한다.
- `records_changed` 실시간 알림, 앱 연결/재접속/기록 탭 진입 및 15초 주기 확인을 함께 사용한다.
- 저장이 실패하면 동기화 커서를 전진시키지 않는다. 같은 페이지를 다시 받아도 중복 사건이 생기지 않는다.
- DB 식별자(`epoch`)가 바뀌면 커서를 초기화한다. 기기 파일은 서버 주소/구급차별로 분리한다.
- 인계확인서 수동 수정은 기기 outbox에 먼저 저장한다. 같은 요청 ID의 재전송은 서버에서 한 번만 적용한다.
  다른 기기의 수정과 버전이 겹치면 기록 탭에서 **서버 기록 사용 / 내 수정으로 다시 저장** 중 선택한다.

## 최초 설정

대원 계정/소속 로그인은 아직 없다. 실시간 `identify`의 구급차 ID만 믿고 과거 기록을 열어주지 않고,
운영자가 발급한 구급차별 기록 동기화 키를 추가로 검증한다. 이 기능이 기존 실시간 API 전체에 인증을 추가하는 것은 아니다.

hub를 실행하는 장비에서 같은 Python 환경으로 실행한다(아래 ID는 실제 소속 구급차 ID로 바꾼다).

```bash
conda activate rookie_hub
python hub/record_archive.py grant SEL0001
```

출력된 키는 한 번만 표시되며 서버에는 SHA-256 지문만 저장된다. 새 기기마다 같은 apid로 별도 키를 발급할 수도 있다.
앱을 최신 빌드로 설치한 뒤 설정에서 **hub 주소 / 소속 구급차 ID / 기록 동기화 키**를 입력하고 적용한다.
과거 기록을 조회할 기기는 `auto` 대신 고정 구급차 ID를 사용한다. 키는 기기의 Keychain에 보관한다.
서버 코드 업데이트 뒤 hub를 재시작한다. 키를 발급한 이후에는 hub 재시작 없이 사용할 수 있다.

키를 분실하거나 접근 권한을 회수할 때:

```bash
python hub/record_archive.py revoke SEL0001
```

해당 구급차에 발급한 모든 키가 폐기된다. 계속 사용할 기기에는 새 키를 발급한다.
키 없는 기기도 기존 통화/이송 흐름과 그 기기에 저장된 기록 조회는 계속 사용할 수 있지만 과거 기록을 다운로드할 수는 없다.

## 저장소와 운영 범위

- `HUB_RECORD_DB_PATH`로 DB 경로를 바꿀 수 있다. 기본은 `HUB_STATE_PATH` 옆의 `case_records.sqlite3`다.
  CLI 키 발급에도 서버와 같은 경로 설정을 사용해야 한다.
- SQLite WAL 모드와 트랜잭션을 사용한다. 실행 중 백업은 SQLite backup API를 사용하거나 hub를 종료한 뒤 DB 파일을 복사한다.
- 서버가 기록을 모으기 시작하기 전의 과거 데이터는 기존 기기가 이관해야 볼 수 있다. 해당 기기와 서버 양쪽에 없는 이력은 복원하지 못한다.
- 설정한 apid 하나의 범위다. 센터 전체 구급차를 묶는 소속 권한, 개인 로그인/전입·전출 관리, Android 기록 클라이언트와 iPad의 과거 기록 전체 조회는 별도 범위다. iPad 현재 사건 수정 공유는 아래 경로로 제공한다.
- 실제 두 기기의 화면/절전/네트워크 전환 동작은 기기 설치 후 확인한다.

## WebSocket 계약

기존 `/ws/dashboard`를 사용하므로 공개 터널에 새 HTTP 경로를 열 필요가 없다.
모든 요청은 `identify(role=ambulance,id=apid)` 이후에 보내고 `requestId`와 `token`을 포함한다.

| 요청 | 추가 필드 | 응답 |
|---|---|---|
| `record_sync` | `cursor`, `epoch` | `record_sync_result`: epoch, cursor, hasMore, records |
| `record_import` | `records`(최대20) | `record_import_result`: records |
| `record_handover` | caseId, revision, edits | `record_handover_result`: conflict, record |

거부/저장 실패는 `record_error`로 응답한다. token은 기록하거나 응답에 넣지 않는다.
`CaseRecord.archiveVersion`은 사건 최신 변경 순번이고 `handoverRevision`은 인계확인서 수동 수정 버전이다.

## 아이폰 ↔ 아이패드 현재 사건 수정 공유

같은 구급대 ID로 연결한 두 네이티브 앱은 `live_case_get`/`live_case_patch`로 인계확인서 수동 수정 칸과 외상 도해의 부위별 외상·처치를 공유한다.
`h:<서식 칸 ID>`와 `b:<부위>:<좌우>` 문자열 키를 사용하며 서식 칸 ID는 두 앱이 동일하다.
기기들은 공통 `dashboard/shared/CaseEditSync.swift`를 컴파일한다. 원문/음성이나 자동값 전체를 이 통로에 복사하지 않는다.
환자 정보·추가 정보의 기존 `patient_override` → `match_result` 전파는 그대로 사용한다.

- 현재 사건의 소속 구급대 소켓만 읽기/쓰기 가능하다. 병원·관제·다른 구급대는 받지 않는다.
- 최초 읽기 때 서버가 사건별 증표를 준다. 기기는 수정 대기열과 함께 이를 보관하여 사건 종료 직전 저장한 오프라인 수정도 재전송할 수 있다.
  종료 후에는 그 증표와 같은 구급대 신원이 모두 있어야 하며, 새 접속자에게 과거 사건 내용을 방송하지 않는다. 증표를 로그에 남기지 않는다.
- `changes`는 변경한 칸만, `base`는 편집을 시작했을 때의 값이다. 삭제/자동값 복원은 JSON null이다.
  서로 다른 칸은 합치고 같은 칸이 다르면 `conflicts`를 돌려준다. 앱에서 서버 값 사용/내 수정 재저장을 명시적으로 선택한다.
- 성공한 요청 ID는 DB 영수증으로 중복 적용을 막는다. 저장을 확정한 뒤 같은 구급대의 다른 기기에 `live_case_state`를 보낸다.
- 인계확인서 칸과 도해 수정은 SQLite 원본에 보관된다. 인계확인서 수동 수정은 기존 기록 보관소의 `handoverEdits`/버전에도 반영된다.
- 앱은 수동 수정 대기열을 기기에 먼저 저장하고 재접속/주기 확인 때 재전송한다. 서버 저장 실패·충돌은 동기화 완료로 표시하지 않는다.
- 기존 기기 인계확인서는 최초 연결 때 서버 수동 수정 버전이 0일 때만 이관한다. 서버에서 이미 수정/초기화한 값을 되살리지 않는다.
- 서식을 열어 둔 상태에서 상대 기기의 수정이 오면 손대지 않은 칸만 따라갱신하고 직접 편집 중인 칸은 보존한다.
- 환자 정보/추가 정보의 기존 전송은 연결 실패 시 오류를 표시하고 저장 완료로 간주하지 않는다. 이 대기열의 자동 재전송 범위는 인계확인서·도해의 수동 수정이다.

과거 기록 전체 다운로드의 기존 구급대별 동기화 키 검증은 그대로다. 현재 사건 공유를 위해 기록 키를 입력할 필요는 없다.
이전에 서버와 한 번도 연결하지 못해 사건 증표를 받지 못한 수정은 사건 종료 후 자동 전송할 수 없으므로 대기열에 남기고 완료로 표시하지 않는다.
기존 사건/권한 구분을 유지하기 위한 제한이며, 기기에 있는 값을 삭제하지 않는다.

적용: hub 재시작 + 양쪽 네이티브 앱 최신 빌드 설치. 두 앱이 같은 구급대(시연 SEL0111)를 사용해야 한다.

검증:

```sh
python hub/test_live_case_socket.py
python -m unittest discover -s hub -p test_live_case_edits.py
sh dashboard/shared/tests/run.sh
```

두 기기의 실제 키보드 편집·절전/네트워크 전환은 설치 후 최종 확인한다.
