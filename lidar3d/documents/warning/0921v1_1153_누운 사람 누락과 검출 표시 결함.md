## 1. 크기 필터 — 높이 하한이 있다

## 3. 조각 1271이 넓은 이유 — H1 배제, H3 유력

| 가설 | 결과 |
|---|---|
| **H1** 바닥 띠 때문에 넓다 | ❌ **배제** |

**H1 검증** — 바닥에서 잘라내도 좁아지지 않는다:


**H2 확인 불가** — TSDF는 어느 프레임이 어느 정점에 기여했는지 **기록하지 않는다.**
계측 코드를 넣지 않고는 역추적할 수 없다. 수정 단계에서만 가능하다.

## 5. 참고 — 검출 재생 화면의 경계상자 결함

**증상**: 사람이 둘 인식돼도 **하나의 경계상자**로 묶여 표시된다.

**원인 — YOLO가 아니라 표시 코드의 결함이다.**

`scripts/export_detection_overlay.py:69-73`:
```python
x0 = min(p[0] for poly in polys for p in poly)   # ← 모든 덩어리에 대해 min/max
y0 = min(p[1] for poly in polys for p in poly)
x1 = max(p[0] for poly in polys for p in poly)
y1 = max(p[1] for poly in polys for p in poly)
frames[key] = {"polys": polys, "bbox": [x0, y0, x1, y1], "n": len(polys)}
```

**덩어리별 bbox가 아니라 전체를 합친 하나의 bbox**를 저장한다.
`detect.html`은 그 값을 그대로 그린다.

**영향 범위**:
```
덩어리 2개 이상인 프레임: 229개 중 90개 (39%)

예) 프레임 105 — 덩어리 3개
    합집합 bbox : 0.93 x 0.70  (화면 비율)
    덩어리0     : 0.06 x 0.11
    덩어리1     : 0.91 x 0.66
    덩어리2     : 0.10 x 0.09
```

**빨간 마스크는 덩어리별로 정확히 분리돼 있다.** 잘못된 것은 초록 경계상자뿐이다.
라벨의 `person ×N` 개수도 정확하다.

> ⚠️ **오해 방지**: 이 화면을 보고 "YOLO가 두 사람을 하나로 합쳤다"고 판단하면 안 된다.
> 검출과 마스크는 정상이고, 시각화만 틀렸다.

**수정 방향** (미실행): `polys` 각각의 bbox를 따로 저장하고
`detect.html`이 덩어리마다 박스를 그리면 된다. 하류 영향은 없다 —
이 필드는 재생 화면에서만 쓰인다.
