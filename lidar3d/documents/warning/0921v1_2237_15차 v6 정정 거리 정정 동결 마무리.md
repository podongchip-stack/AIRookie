## 1. v6 배경 인물 — **14차 분류가 틀렸다**

### 문제

14차는 0921v6의 배경 2명을 "검출 자체가 없는 인물(0920v2 인물 B와 같은 유형)"으로
분류했다. 그런데 v6는 **162프레임 중 65프레임에서 conf 0.18~0.50으로 꾸준히 검출**된다.
같은 유형이 아니다.

### 1-1 · 1-2. 저신뢰 검출을 3D로 추적한 결과

`scripts/diagnostics/v6_background.py` (신규)

```
저신뢰 검출 79개 중 3D 산출 가능 79 / 뎁스 부족 0

카메라 거리        중앙 2.14m   최대 3.21m      (융합 상한 4.0m 안쪽)
융합된 전체 장면까지  중앙 3.9cm   5cm 이내 59%
객체 볼륨까지       중앙 4.3cm   5cm 이내 57%
사람 조각 p01까지   중앙 1.17m
```

**형상은 존재한다.** 뎁스가 없어서도, 거리가 멀어서도 아니다.

### 정정 — 배경 인물 1명은 이미 인정되고 있었다

프레임별로 보면 저신뢰 검출이 두 무리로 나뉜다.

| 프레임 | 3D 중심 | p01까지 | p02까지 | 해석 |
|---|---|---|---|---|
| 25~60 | (1.33, 0.70, 2.60) | **0.04m** | 1.46m | 앞 사람 A의 저신뢰 중복 검출 |
| 90~119 | (1.40, 0.70, 4.35) | 1.17m | **0.01~0.12m** | **배경 인물 = `fused_person_02`** |
| 87 | (3.42, 1.02, 4.58) | 2.30m | 1.65m | 또 다른 위치 — 검출 1회뿐 |

**`fused_person_02`가 배경 인물이다.** 14차에서 "책상 물건인지 배경 인물인지 불확실"로
남겼던 조각의 정체가 밝혀졌다.

따라서 v6 채점은 **놓침 2 → 1**, **사람 인정 1/3 → 2/3**, **잡동사니 1 → 0** 으로 바뀐다.

### 1-3. 새 한계 유형 등록 — "검출은 있으나 conf 0.5 미만"

| | 0920v2 인물 B | **0921v6 배경 인물** |
|---|---|---|
| 검출 | **집단 자체가 없음** | 65/162 프레임, conf 0.18~0.50 |
| 형상 | 확인 불가 | **존재** (장면까지 3.9cm) |
| 결과 | 위치 특정 실패 | **1명은 조각으로 인정됨** |

등만 보이거나 부분만 노출된 인물이 여기 해당한다.
신뢰도가 문턱 0.50을 못 넘어, **고신뢰 뒷받침이 우연히 몇 개 생겨야만 인정된다.**

**해결하지 않는다.** 문턱을 낮추면 잡동사니가 급증한다(0921v9 참조).
동결 문서 4-2절에 기록했다.

## 2. LiDAR 측정 거리 — **2.5m도 5m도 아니다**

### 모순의 정체

- 설계 검토 문서: "LiDAR 유효 측정 반경 약 2.5m (사양 5m 아님)"
- 14차 v6 측정: "뎁스 최대 5.80m, 2.5m 초과가 46% 유효"

둘 다 **서로 다른 것을 재고 있었다.**

### 2-1. 실제 거름망 — 신뢰도맵이 아니다

**ARKit 신뢰도맵(`depth/conf_*.bin`)은 세션마다 기록되지만
어떤 파이프라인 스크립트도 읽지 않는다** (grep 0건).
(형식 확인: 화소당 1바이트, 값 0/1/2 — ARKit 표준. 실측 v6 첫 프레임에서 값 2가 82%)

실제 거름망은 `scripts/stage2_fuse.py`의 세 가지다.

1. `clean(maxd=4.0)` — 0 이하 또는 **4.0m 초과를 버림** (코드 상수)
2. 이웃 화소와 **상대 차이 4% 초과를 버림** (경계 튐 제거)
3. `depth_trunc=4.0` — RGBD 생성에서 한 번 더 자름

### 2-2. 두 거리의 분포 (새 10세션, 3,371만 화소)

| 구분 | 화소 | 중앙 | 90% | 99% | 최대 |
|---|---|---|---|---|---|
| **(a) 뎁스 값이 존재하는 거리** | 33,718,272 | 1.46m | 3.19m | 4.79m | **9.49m** |
| **(b) 융합에 쓰여 3D 형상이 생기는 거리** | 31,103,135 | 1.43m | 3.00m | 3.83m | **4.00m** |

전체 생존율 **92.2%**.

거리 구간별 생존율:

```
  0.0~1.0m   96.0%        3.0~3.5m   93.6%
  1.0~2.0m   95.3%        3.5~4.0m   95.2%
  2.0~2.5m   93.6%        4.0~5.0m    0.6%   ← 여기서 잘린다
  2.5~3.0m   92.2%        5.0m 초과   0.0%
```

- **4.0m에서 딱 잘린다.** 4.0~5.0m 생존율 0.6%, 그 위는 0%.
- 융합 사용 화소의 **2.5m 이내 83.2% / 3.0m 이내 90.0% / 4.0m 이내 100%**

세션별로는 융합 사용 중앙값이 1.04m(v3) ~ 2.73m(v8)로 장면에 따라 크게 다르다.
**최대값은 10세션 전부 정확히 4.00m다** — 센서가 아니라 코드가 정한 값이라는 증거다.

### 2-3. 외부 문서에 쓸 표현

> **"뎁스 값 자체는 최대 약 9.5m까지 얻어지지만, 파이프라인이 4.0m에서 잘라내므로
> 3D 형상이 생성되는 범위는 4.0m 이내이며, 실측상 융합에 쓰인 화소의 83%가 2.5m 이내다."**

짧게:
> **"3D 형상 생성 범위는 4.0m 이내(파이프라인 설정값), 실사용 대부분은 2.5m 이내"**

**"유효 반경 2.5m"는 쓰지 말 것.** 센서 한계도 필터 기준도 아니고,
데이터가 몰려 있는 거리일 뿐이다.

## 4. 코드 동결

### git 저장소가 없었다

프로젝트가 git 저장소가 아니어서 **초기화부터 했다.**
그대로 커밋하면 **촬영 세션 원본 2.7GB(개인 영상 포함)와 토큰 파일이 들어간다.**
먼저 `.gitignore`를 고쳤다.

추가한 항목:
```
.lidar_tunnel      # 기존 .gitignore에 빠져 있었다
*.pem  *.key
server/sessions/   # 2.7GB, 개인 영상
models/  *.pt      # 147MB (기존에 *.pth/*.ckpt만 있었다)
.DS_Store
```

## 5. 미해결 과제 (우선순위 순)

### 1순위 — AGPL-3.0 모델 교체

`ultralytics` 패키지와 `yolov8l-seg` 가중치가 AGPL-3.0이다.
제출·배포 형태에 따라 **소스 공개 의무가 생길 수 있다.**
**기술 문제가 아니라 법적 제약이므로 가장 먼저 처리해야 한다.**

### 2순위 — 저신뢰 검출 인물 구제

1절의 새 유형이다. 문턱 0.5를 그냥 낮추면 잡동사니가 급증한다.
대안 후보 (미검증): **시간적 연속성** — 같은 위치에서 연속 프레임에 저신뢰 검출이
이어지면 승격. v6 실측으로 **65/162 프레임 연속 검출**이 확인됐으니 신호는 충분하다.

### 3순위 — 이동에 의한 쪼개짐

v8·v10에서 확인. 시간창(`WIN`, 현재 0=제한 없음) 파라미터 실험.
**주로 처치자·목격자에게 생기고 환자는 누워 있어 영향이 적으므로** 우선순위는 낮다.

### 그 밖에

- 고신뢰 1개 면제의 최소 검출 수 도입 (v9에서 conf 0.52 하나로 잡동사니가 승격됐다)
- 적중률 지표에 거리 항 보강 (사람 옆 사물이 높게 나온다)
- **설계 검토 문서의 "유효 반경 2.5m" 표현 수정** (2-3절 문장으로 교체)
