### A-3. 수평 단면 — 깨끗이 2명으로 나뉘지는 않는다

## B. 사람 구분 정보가 어디서 사라지는가

### B-1. `stage1_masks.py` — 논리합으로 합친다

```python
msk = np.zeros((H,W), dtype=bool)          # 프레임당 배열 하나
if r.masks is not None:
    md = r.masks.data.cpu().numpy()        # (n, mh, mw) — 인스턴스별로 들어온다
    for k, b in enumerate(r.boxes):
        if model.names[int(b.cls)] not in TARGETS: continue
        mk = (md[k] > 0.5).astype(np.uint8)
        mk = cv2.resize(mk, (W, H), interpolation=cv2.INTER_NEAREST)
        msk |= mk.astype(bool)             # ← 여기서 "몇 명인지"가 소실된다
masks[idx] = msk
```

저장 형식: `dtype=bool`, `shape=(192,256)` — **인스턴스 구분 없음.**

### B-2. 라벨맵으로 바꿀 때 깨지는 지점 — **3개 파일**

제안 형식: `uint8` 라벨맵 (0=배경, 1..N=사람 인스턴스)

| 파일 | 지점 | 영향 |
|---|---|---|
| `stage1_masks.py` | 120행 저장 | `bool` → `uint8` 라벨맵 |
| `stage2_fuse.py` | 52행 `.any()` | `>0` 으로 감싸면 동작 |
| 〃 | 66행 `last=masks[vfi]` | 그대로 (의미만 바뀜) |
| 〃 | 72행 `db[last]=0` | `db[last>0]=0` |
| 〃 | 75행 `do[~last]=0` | `do[last==0]=0` |
| 〃 | **85행 `connectedComponents(last)`** | **불필요해진다** — 아래 참조 |
| `export_detection_overlay.py` | 58행 `findContours(m)` | 라벨별로 돌리면 **오히려 개선** |

**85행이 핵심이다.** 지금은 합쳐진 마스크를 다시 연결 덩어리로 쪼개 깊이 게이트를
적용하는데, 라벨맵이 있으면 **YOLO 인스턴스별로 바로** 적용할 수 있다.
붙어 있는 두 사람도 라벨이 다르면 따로 처리된다.

`export_detection_overlay.py`는 라벨별 윤곽선을 내면 C-1에서 만든
덩어리별 경계상자가 **진짜 인스턴스별 상자**가 된다 (지금은 연결 성분 기준).

### B-3. 근접 그룹화(0.8m) — **원인이 아니다**

큰 조각들의 중심 간 거리:

```

조각3        -      2.87     1.53     1.40     1.15
조각1271   2.87       -      1.52     4.25     3.89
```

0.8m 안에 드는 쌍은 **조각399 ↔ 조각191 (0.72m, 각 0.33㎡)** 하나뿐이다.

**조각 3은 이미 하나의 연결 성분**이라 그룹화 반경을 줄여도 분리되지 않는다.
**TSDF 융합 단계에서 이미 붙었다.**

## D. 확인 불가 / 남은 위험

- **조각 3의 정확한 인원** — 인스턴스 3~4개 중 중복을 구분하지 못했다
- **프레임 간 사람 추적** — YOLO 인스턴스 번호는 프레임마다 바뀐다.
  라벨맵을 도입해도 "프레임1의 인스턴스0 = 프레임2의 인스턴스0"이라는 보장이 없다.
  **이것이 라벨맵 방안의 가장 큰 미검증 위험이다.**
- 다른 세션에서 같은 현상이 나오는지 — `v3`만 측정했다
