## 3. 마스크 신뢰도 — 별도 파일 방식

### 3-1. 저장 형식

**이 프로젝트에 이미 같은 방식의 선례가 있다.** `scene_mesh_faces_class.bin`이
`server/viewer/index.html:327`에서 쓰이고 있고, 주석에 이유까지 적혀 있다 —
*"three.js PLYLoader도 Open3D처럼 PLY 면의 커스텀 property를 돌려주지 않는다."*

같은 패턴을 따른다.

```
<메시이름>_confidence.bin
  [0:4]   매직    "LCF1" (ASCII 4바이트)
  [4:8]   uint32  정점 수 N
  [8:16]  uint64  정점 좌표 해시 (아래 3-3)
  [16:  ] float32 × N   신뢰도 0.0~1.0 (PLY 정점 순서와 동일)
```

- `float32`를 쓰는 이유: 비율은 연속값이고, 9차에서 **삭제분의 35.7%가 0.3~0.55 구간**에
  몰려 있었다. 양자화하면 바로 그 구간을 뭉갠다.
- 크기: v3 조각 하나 5.5만 정점 기준 **약 220 KB.** 무시할 만하다.

### 3-2. 뷰어 변경 범위

현재 사람 메시 로딩은 `server/viewer/index.html:714` 부근이다.

필요한 변경 (**실제 수정은 하지 않았다**):

1. **`server/app.py`** — 변경 불필요. `/session/<id>/file/<name>`이 이미 임의 파일을 내려준다.
2. **`server/viewer/index.html` (약 705~725행)**
   - `_confidence.bin`을 `fetch`한다. 없으면 기존과 동일하게 동작한다(선택적 기능).
   - 헤더 검증 후 `geo.setAttribute('conf', new THREE.BufferAttribute(arr, 1))`
   - 재질을 `MeshStandardMaterial` + `onBeforeCompile`로 바꿔, 낮은 `conf`를 회색 쪽으로
     섞는다. 정점 색이 이미 있으므로 **색을 덮지 말고 섞어야** 한다.
     ```glsl
     // 정점 셰이더: varying float vConf;  vConf = conf;
     // 프래그먼트: diffuseColor.rgb = mix(vec3(0.55), diffuseColor.rgb,
     //                                   smoothstep(0.25, 0.65, vConf));
     ```
   - 범례에 "흐린 부분 = 마스크 일관성 낮음" 한 줄과 토글 버튼.
3. **`scripts/stage2_fuse.py`** — 삭제 대신 `.bin`을 쓴다 (4절 참조).

**투명도(`transparent:true`)는 쓰지 않기를 권한다.** 사람 메시는 양면 렌더라
반투명으로 하면 뒷면이 비쳐 형태가 더 알아보기 어려워진다. 회색 혼합이 안전하다.

> ⚠️ 셰이더 수정은 실제로 시험하지 않았다. `onBeforeCompile` 경로는
> 브라우저에서 직접 확인해야 한다. (과거에 `node --check`만 믿었다가
> 뷰어 모듈 전체가 죽은 적이 있다.)

### 3-3. 정점 순서가 어긋나는 위험

**확인한 사실:** `scripts/color_mesh.py`는 `vertex_colors`만 덧붙이고
정점 배열을 그대로 둔다(`color_mesh.py:145`). 실측으로도 `_colored.ply`는
원본과 정점 수·순서가 같다. **뷰어가 `_colored.ply`를 우선 로드해도 사이드카는 유효하다.**

막는 방법 (2중):

1. **정점 수 검증** — `N !== geo.attributes.position.count` 이면 사이드카를 무시한다.
   값이 싸고 대부분의 사고를 잡는다.
2. **좌표 해시** — 정점 수가 같아도 순서가 바뀔 수 있다.
   처음 1,000개와 마지막 1,000개 정점의 `float32` 좌표 비트를 FNV-1a로 섞은
   uint64를 헤더에 넣고, 뷰어에서 같은 계산을 해 비교한다.
   전체를 해싱하지 않는 이유는 브라우저 비용 때문이다.

불일치 시 **조용히 무시하고 기존대로 그린다.** 경고는 콘솔에만 남긴다.
신뢰도 표시는 보조 기능이므로, 이것 때문에 메시가 안 보이면 안 된다.

> 따라서 요청받은 "묶음 반영 계획"을 그대로 쓰지 않고,
> **무엇을 반영할 수 있고 무엇을 반영하면 안 되는지**로 정리한다.

### 4-1. 반영 권고: 크기 필터 면제 (단독)

**파일: `scripts/stage2_fuse.py`** (현행 158~185행 부근)

```diff
-        if not (0.30<d[1]<2.2 and 0.15<d[0]<2.0 and 0.15<d[2]<2.0):
+        # 고신뢰(conf>=0.5) 군집이 이 조각을 뒷받침하면 크기 필터를 건너뛴다.
+        # 크기는 모양으로 사람을 추정하는 장치이고, 군집은 검출 자체가 근거다.
+        backed = cluster_backing(pts)      # 신규 도우미
+        if not backed and not (0.30<d[1]<2.2 and 0.15<d[0]<2.0 and 0.15<d[2]<2.0):
```

- **영향**: v3 `review_blob` 2개 중 누운 사람이 **사람으로 승격**된다.
  v1·v2는 면제가 걸리는 조각이 없거나(v1) 이미 사람인 조각뿐(v2)이라 **변화 없음**.
- **되돌리기**: `backed`를 항상 `False`로 두면 현행과 완전히 동일해진다.
  한 줄 플래그로 끌 수 있게 만들 것.
- **선행 조건**: 계층1 군집 계산을 파이프라인에 넣어야 한다 (현재는 진단 스크립트에만 있다).
  이것이 이 변경의 **실제 작업량 대부분**이다.

### 4-2. 반영 보류: 층 분리 배정

**넣으면 안 된다.** v1에서 사람 3명이 6명이 되고 투영 대응이 99.3% → 2.6%로 무너진다.

넣으려면 **적용 조건**이 필요하다. 예를 들어
*"한 조각이 고신뢰 군집 2개 이상의 관측에 동시에 대응할 때만 분리한다"*
— v3 조각 3은 해당하고, v1의 온전한 사람들은 해당하지 않는다.
**이 조건은 아직 검증하지 않았다.** 다음 차수 과제다.

### 4-3. 반영 보류: 반경 밖 정점 → 불확실 조각

층 분리 배정에 딸린 기능이라 4-2와 함께 보류한다.
단독으로도 v1의 "무근거 나머지 3조각"(적중률 36.7 / 73.6 / 61.4%)을
사람으로 세어 **과다 계수**를 일으킨다.

### 4-4. 반영 권고: 마스크 신뢰도 별도 파일 (삭제 철회)

**파일: `scripts/stage2_fuse.py`, `server/viewer/index.html`**

```diff
-        # 마스크 일관성 낮은 정점 삭제
-        keep = ratio >= 0.55
-        sub = sub.select_by_index(np.nonzero(keep)[0])
+        # ⚠️ 삭제하지 않는다. 9차 측정 — 삭제분의 47%가 유지 정점 5cm 이내였고
+        #    투영 덮음이 50.1% → 44.3%로 떨어졌다. 팔·가장자리를 함께 깎았다.
+        write_confidence_sidecar(f"{S}/fused_person_{n:02d}_confidence.bin", ratio)
```

- **영향**: **기존 판정(v1~v3 사람 수)은 전혀 바뀌지 않는다.** 파일 하나가 늘 뿐이다.
  뷰어에서 신뢰도 낮은 부분이 흐리게 보인다.
- **되돌리기**: `.bin` 파일을 지우면 뷰어가 자동으로 기존 표시로 돌아간다.
  **파이프라인 코드를 되돌릴 필요조차 없다.** 가장 안전한 변경이다.
- **순서**: 뷰어 셰이더를 **실제 브라우저에서 확인한 뒤** 파이프라인에 넣을 것.

### 4-5. 반영 권고: v3 무근거 조각 2개 (적중률 8.0% / 14.1%)

2-3에서 드러난 **기존 결함**이다. 사람이 아닌 것이 사람으로 세어지고 있다.
다만 사용자가 정한 비대칭 비용상 **"사람으로 세지 않기"로 바꾸는 것은 위험하다.**
지금은 **보고만 하고 건드리지 않는다.**

### 요약

| 변경 | 권고 | 기존 판정 변화 | 되돌리기 |
|---|---|---|---|
| 크기 필터 면제 | **반영** | v3 누운 사람 승격, v1·v2 무변화 | 플래그 한 줄 |
| 층 분리 배정 | **보류** | v1 3명→6명 (악화) | — |
| 반경 밖 → 불확실 조각 | **보류** | v1 과다 계수 | — |
| 마스크 신뢰도 사이드카 | **반영** (뷰어 검증 후) | 없음 | `.bin` 삭제 |

## 5. 미해결 / 확인 불가

- 9차 342/17 과 10차 341/18 의 **1개 차이를 설명하지 못했다.**
- 덮음 <10% 인 6개(화면 끝 띠)를 결과물에 넣는 방법은 **검증하지 않았다.**
  기하는 배경 메시에 있으므로 잃어버린 것은 아니다.
- 층 분리 배정의 **적용 조건**("군집 2개 이상 대응 시에만 분리")은 미검증이다.
- 뷰어 셰이더(`onBeforeCompile`) 경로는 **브라우저에서 확인하지 않았다.**
- v1 / v2의 **정답 인원 수는 여전히 미확정**이다. v1은 현행 3명이 대응 99.3%로
  맞아 보이지만, **촬영자 확인은 받지 않았다.**
- 반경 0.374 m 는 여전히 **관측 13개 기반**이다.
