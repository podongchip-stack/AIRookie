# 플랫폼 독립 입력 계약 — Android 이식 준비

**작성 2026-09-18 02:46 · v1**
**대상: 안드로이드 앱 개발자 + 맥 파이프라인 담당자**

맥 쪽 3D 파이프라인이 iOS/ARKit에 묶이지 않도록, **앱이 지켜야 할 파일 규약**만 정의한다.
이 규약만 지키면 안드로이드 앱이든 아이폰 앱이든 **같은 스크립트가 그대로 동작한다**.

---

## 1. 왜 이 계약이 필요한가 — 실측 근거

ARKit이 만들어주는 메시에 의존하면 **같은 하드웨어 세대끼리도 결과가 갈린다.**
2026-09-18 같은 방·같은 시각 실측:

| | iPhone 15 Pro (iOS 26.6.1) | iPhone 12 Pro (iOS 26.2.1) |
|---|---|---|
| ARKit 메시 표면 | 25.1 m² | 107.9 m² |
| 뎁스 신뢰도 "높음" | **0.00%** | **73.56%** |
| 뎁스 값 자체 | 0.53~8.57 m (정상) | 0.25~6.60 m (정상) |

**뎁스 원본은 양쪽 다 멀쩡한데 ARKit의 판정만 갈렸다.** 플랫폼이 만들어주는 메시를
그대로 쓰면 이런 변동을 통제할 수 없다. 안드로이드를 추가하면 변동이 더 커진다.

→ **앱은 원자료(뎁스·포즈·intrinsics)만 내보내고, 3D 재구성은 맥에서 한다.**
   실측으로 이 방식이 15 Pro의 표면을 25.1 → 257.1 m²로 되살렸다 (10.2배).

## 2. 앱이 반드시 내보내야 하는 것 (필수)

### 2.1 `depth/depth_%06d.bin`
- **raw little-endian Float32**, row-major, **행 패딩 없음(tightly packed)**
- 단위 **미터**. 측정 실패 픽셀은 **0**
- 크기는 `metadata.json`의 `depth_width × depth_height`

> ⚠️ 행 패딩 주의: `CVPixelBuffer`(iOS)나 `Image`(Android) 모두 `rowStride`가
> `width × 4`보다 클 수 있다. 그대로 덤프하면 이미지가 비스듬히 밀린다. **행 단위로 복사할 것.**

### 2.2 `depth/index.csv`
```csv
depth_index,timestamp,video_frame_index,depth_file,conf_file,smooth_depth_file,smooth_conf_file
0,110497.852715,0,depth_000000.bin,conf_000000.bin,,
```
- `timestamp`는 **포즈와 같은 시계**여야 한다 (아래 2.3과 정확히 일치해야 조인된다)
- `video_frame_index`는 대응 영상 프레임 번호, 없으면 `-1`
- 뒤 두 열은 선택 사항. 비워도 된다

### 2.3 `arkit_pose.csv` (이름은 유지 — 서버 화이트리스트에 등록돼 있다)
```csv
frame_index,timestamp,tx,ty,tz,qx,qy,qz,qw,tracking_state,tracking_state_reason,fx,fy,cx,cy
```
| 항목 | 규약 |
|---|---|
| 좌표계 | **오른손, Y축이 중력 반대(위), 미터** |
| `tx,ty,tz` | 카메라 위치 |
| `qx,qy,qz,qw` | **camera-to-world** 회전. 카메라는 자신의 **-Z** 방향을 본다 |
| `fx,fy,cx,cy` | **영상 해상도 기준** intrinsics (뎁스 해상도 아님) |
| `tracking_state` | 0=불가 1=제한 2=정상. **2만 융합에 쓰인다** |

> ARCore의 `Frame.getCamera().getPose()`는 OpenGL 관례(-Z 전방, Y 위)로 ARKit과 **같다.**
> 즉 안드로이드는 좌표 변환 없이 그대로 기록하면 된다.

### 2.4 `metadata.json` — 최소 필수 키
```json
{
  "capture_mode": "lidar_arkit" 또는 "depth_arcore",
  "reconstruction_required": false,
  "depth_width": 256, "depth_height": 192,
  "video_frame_width": 1920, "video_frame_height": 1440,
  "device": "iPhone 12 Pro",
  "coordinate_system": "right-handed, Y-up (gravity), meters",
  "pose_convention": "camera-to-world, camera looks down -Z"
}
```

## 3. 지켜야 할 불변식

1. **좌표를 앱에서 변환하지 않는다.** 플랫폼 원본 그대로 기록하고, 변환은 맥에서 한다.
2. **timestamp를 보정하지 않는다.** 뎁스·포즈·영상이 **같은 시계의 같은 값**이어야
   근사 매칭 없이 정확히 조인된다. (현재 iOS 앱은 205/205 프레임이 정확히 일치한다.)
3. **intrinsics는 영상 해상도 기준**으로 기록한다. 맥에서 뎁스 해상도로 스케일한다.
4. **영상에 회전 transform을 붙이지 않는다.** 붙이면 intrinsics와 픽셀이 어긋나
   **에러 없이 조용히 틀린 재투영**이 나온다.

## 4. Android 매핑 (ARCore)

| 필요한 것 | ARCore API |
|---|---|
| 뎁스맵 | `Frame.acquireDepthImage16Bits()` — **밀리미터 UInt16**이므로 `/1000.0` 해서 Float32 미터로 변환 |
| 신뢰도 | `Frame.acquireRawDepthConfidenceImage()` (Raw Depth 사용 시) |
| 카메라 포즈 | `Frame.getCamera().getPose()` — 위치 + 쿼터니언 |
| intrinsics | `Camera.getImageIntrinsics()` — focal length, principal point |
| 추적 상태 | `Camera.getTrackingState()` → TRACKING=2, PAUSED=1, STOPPED=0 |

### 주의할 차이
- **단위**: ARCore 뎁스는 **밀리미터 정수**다. 반드시 미터 Float32로 변환해 저장한다.
- **해상도**: ARCore 뎁스는 기기마다 다르다(보통 160×120). `metadata.json`에 실제값을 쓴다.
- **ToF 유무**: ToF 센서가 없는 기기는 뎁스가 추정값이라 훨씬 부정확하다.
  `metadata.json`에 `depth_source: "tof" | "estimated"`를 남겨 맥에서 구분하게 한다.
- **좌표계**: ARCore는 ARKit과 같은 관례라 변환이 필요 없다. 이 점이 이식을 쉽게 만든다.

## 5. 맥 파이프라인이 제공하는 것 (앱과 무관하게 동작)

| 스크립트 | 하는 일 |
|---|---|
| `scripts/fuse_depth.py` | 뎁스+포즈 → 균일 해상도 메시 (신뢰도 불필요) |
| `scripts/fuse_adaptive.py` | **배경 거칠게 + 관심 객체 정밀하게** |
| `scripts/merge_sessions.py` | 여러 기기/세션 병합 (4자유도 정합) |
| `scripts/detect_objects_3d.py` | YOLO 검출 → 3D 위치 (미터) |

전부 **CSV + .bin만 읽는다.** ARKit/ARCore 호출이 없다.

## 6. 검증 방법 (안드로이드 앱 완성 후)

1. 같은 공간을 iOS 앱과 안드로이드 앱으로 각각 촬영
2. 각각 `fuse_depth.py` 실행 → 표면적·바닥 평면 이탈량 비교
3. `merge_sessions.py`로 두 세션 병합 → fitness > 0.15, RMSE < 3cm면 좌표계 규약이 맞은 것

**3번이 통과하면 규약이 정확히 구현된 것이다.** 좌표계나 단위가 틀리면 정합이 실패한다.
