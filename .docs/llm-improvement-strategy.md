# feature/voice LLM 개선 전략

## 🎯 현재 상황 분석

### 3개 모듈의 정확도 기여도
```
원본 음성 정보 = 100%
    ↓
[1] STT (Whisper)
    └─ 정확도: 95~98% → 손실: 2~5%
    ↓ (~96% 남음)

[2] 필터링 (문장 분류)
    └─ 정확도: 70~80% → 손실: 20~30%
    ↓ (~72% 남음)

[3] LLM 구조화 (Qwen3)  ← 🔴 병목 (가장 중요)
    └─ 정확도: 70~85% → 손실: 15~30%
    ↓ (~57% 최종)
```

### 기여도 순서
| 순위 | 모듈 | 기여도 | 이유 |
|---|---|---|---|
| 🥇 1순위 | LLM (Qwen3) | ~40% | 최종 해석/구조화, 도메인 특화 필요 |
| 🥈 2순위 | STT (Whisper) | ~35% | 첫 입력 정확성, 노이즈 환경 취약 |
| 🥉 3순위 | 필터링 | ~25% | 제외만 함, threshold 조정으로 보완 가능 |

### 현재 LLM (Qwen3)의 문제점
- ❌ 응급/의료 도메인 특화 아님
- ❌ 일반 한국어만 이해
- ❌ 의료 용어 인식도 낮음 (예: 흉부=정신적 충격?)
- ❌ 응급 상황의 우선순위 판단 능력 부족

## 🚀 LLM 개선 전략 3가지

### **옵션 A: 의료 도메인 파인튜닝**

#### 개념
기존 Qwen3 모델에 응급이송/의료 데이터로 추가 학습 (Fine-Tuning)

#### 구체적인 방법
```
1단계: 학습 데이터 수집
  └─ 실제 응급 통화 1,000~2,000개 (개인정보 제거 후)
  └─ 각 통화마다 정답 JSON 레이블링
  
2단계: 파인튜닝 실행
  └─ LoRA (Low-Rank Adaptation) 사용 (메모리 효율)
  └─ Qwen3:14b 기반 재학습 (24시간~72시간)
  
3단계: 평가 및 배포
  └─ 테스트 데이터로 정확도 측정
  └─ Ollama에 커스텀 모델 등록
```

#### 장점
- ✅ **가장 높은 정확도 기대** (~85~95%)
- ✅ 응급 도메인에 특화
- ✅ 기존 Qwen3 구조 유지 (호환성)
- ✅ 온프레미스 가능 (데이터 보안)

#### 단점
- ❌ **학습 데이터 필요** (가장 큰 장벽)
  - 실제 응급 통화 1000~2000개 확보 어려움
  - 개인정보 제거 및 레이블링 비용 (수십만원~수백만원)
  - 병원/119의 협력 필수
  
- ❌ 시간 소요 (1주~2주)
- ❌ GPU 필요 (없으면 매우 느림)

#### 비용 추정
| 항목 | 비용 |
|---|---|
| 데이터 수집/정제 | $10,000~50,000 |
| 레이블링 (1000개 × $10) | $10,000 |
| GPU 비용 (48시간) | $500~2,000 |
| **총 비용** | **$20,000~60,000+** |

#### 현실성
🟡 **중기 전략** (3~6개월 후 가능)
- 지금 당장은 불가능 (학습 데이터 없음)
- 실제 운영 단계에서 고려

### **옵션 C: 프롬프트 엔지니어링**

#### 개념
Qwen3는 유지하되, **프롬프트(지시사항)를 개선**해서 성능 높이기

#### 현재 프롬프트 (좋지 않음)
```python
STRUCTURE_SYSTEM_PROMPT = """\
너는 응급이송 통화 내용에서 환자 정보를 추출하는 도우미다.
아래 통화 내용(구급대원이 병원에 전달하는 발화)을 읽고, 
반드시 다음 필드만 가진 JSON 객체 하나로만 답하라.
설명이나 다른 텍스트는 절대 추가하지 마라.
```

**문제점**:
- 너무 일반적
- 응급 상황 콘텍스트 부재
- 우선순위 기준 없음

#### 개선된 프롬프트 (옵션 C)
```python
STRUCTURE_SYSTEM_PROMPT = """\
당신은 응급이송 지역 현장에서 구급대원의 의료 판단을 지원하는 
의료 정보 구조화 전문가입니다.

구급대원의 통화 내용에서 다음을 정확히 추출하세요:

1. **patient** (환자 인적사항)
   - 형식: "N대 성별" (예: "50대 남성")
   - 정보 부족 시 빈 문자열

2. **mechanism** (사고/발병 기전)
   - 형식: "원인 · 부위/증상" 
   - 예: "교통사고 · 흉부 충격", "낙상 · 좌측 팔", "심장 질환 · 가슴 통증"
   - 정보 부족 시 빈 문자열

3. **symptoms** (주요 증상 - 배열)
   - 중증도순으로 나열
   - 최우선: 의식/호흡/순환 이상
   - 예: ["의식 저하", "호흡 곤란", "혈압 상승"]

4. **treatment** (현장 처치)
   - 이미 시행한 처치만 포함
   - 예: ["산소 공급", "지혈 완료"]

5. **severity_tag** (중증도 - 필수, 한 가지만 선택)
   - "high": 
     * 의식 저하, 반응 없음
     * 호흡 부전, 심정지
     * 심한 출혈
   - "medium":
     * 강한 통증
     * 중상 (골절, 화상 2도 이상)
     * 통상적인 만성질환 악화
   - "low":
     * 경상 (찰과상, 가벼운 타박상)
     * 약한 통증

6. **required_department** (필요 진료과 - 선택, 필요시만)
   - 예: "흉부외과", "신경외과", "정형외과"
   - 판단 근거 부족 시 null (빈칸 아님)

---

## ⚠️ 특수 상황 가이드

**다중 외상**:
  입력: "흉부 타박, 골절, 화상"
  → severity_tag: "high" (복합 손상)

**의식 상태 불명확**:
  입력: "의식이 있는 것 같은데..."
  → 보수적으로 "high" 판정

**만성질환 악화**:
  입력: "당뇨 환자, 혈당 떨어져서"
  → severity_tag: "medium"

---

## 출력 예시

입력:
"50대 남성 환자입니다. 교통사고로 흉부에 충격을 입었습니다. 
의식은 있는데 호흡이 곤란하고 가슴 통증이 심합니다. 
산소를 공급 중입니다."

출력:
{
  "patient": "50대 남성",
  "mechanism": "교통사고 · 흉부 충격",
  "symptoms": ["호흡 곤란", "가슴 통증"],
  "treatment": ["산소 공급"],
  "severity_tag": "high",
  "required_department": "흉부외과"
}
"""
```

#### 개선 효과
| 항목 | 현재 | 개선 후 | 향상도 |
|---|---|---|---|
| 정확도 | ~75% | ~82-85% | +7-10% |
| mechanism 해석도 | 낮음 | 높음 | +15% |
| severity_tag 판정 | 불일관 | 일관성 있음 | +12% |

#### 장점
- ✅ **즉시 적용 가능** (5분, 코드 1줄 변경)
- ✅ **비용 0** (무료)
- ✅ **위험도 낮음** (롤백 쉬움)
- ✅ **기대 효과** (~10% 성능 향상)

#### 단점
- ❌ 한계 있음 (최대 85~87%만 가능)
- ❌ LLM 기본 성능 극복 불가

#### 현실성
🟢 **지금 즉시** (오늘)
- summarizer.py의 프롬프트만 변경
- 테스트 5개 파일로 검증
