# Step 4 구현 결과: 필터링 통합 (`filtering.py` 재사용)

> `.docs/voice-live-step4-detailed.md`(개념 가이드)를 따라 구현하고, 실제
> 잡담+의료 발화를 섞어 재생하며 검증한 결과 기록. 코드는 `live_transcribe.py`
> 변경분 참고.

---

## ✅ 한 줄 요약

`live_transcribe.py`에 `MedicalRelevanceFilter`를 통합해, 매 사이클 새로
추가된 턴에 대해 `[점수] 유지/제외` 판정을 출력하도록 했다. 임베딩 모델은
루프 진입 전 1회만 로드하고, 분류 자체는 매 사이클 `all_turn_texts` 전체를
재계산한다(가이드 설계 그대로). 실제 잡담/의료 발화를 섞어 재생해 검증하는
과정에서, **Step 3에서 예고된 "VAD 재판정" 문제가 필터링 결과 자체를
오염시킬 수 있다는 더 구체적인 사례**를 발견했다.

## 🛠️ 구현 내용

```python
# 루프 진입 전 1회만 생성 (임베딩 모델 로딩 비용 절약)
relevance_filter = MedicalRelevanceFilter()

# ... 사이클마다 새 세그먼트를 all_turn_texts에 추가한 뒤 ...

if new_count == 0:
    print("(새 세그먼트 없음)")
else:
    classified = relevance_filter.classify_turns(all_turn_texts)
    for result in classified[-new_count:]:  # 이번 사이클 신규 턴만 출력
        verdict = "유지" if result.is_relevant else "제외"
        print(f"  [{result.score:.3f}] {verdict}  {result.text}")
```

가이드와의 차이점은 없다 — `all_turn_texts` 전체를 매번 재분류하되, 출력은
`classified[-new_count:]`로 슬라이스해서 이번 사이클에 새로 추가된 턴만
보여주는 방식을 그대로 구현했다.

## 🧪 실행 결과 (실제 테스트)

### 테스트 방법

이전 Step들과 마찬가지로 자동화 환경이라 사람이 직접 마이크에 말할 수
없어, macOS `say` 명령으로 스피커에서 음성을 재생하고 동시에
`live_transcribe.py`가 마이크로 그 소리를 다시 캡처하도록 했다(스피커 →
공기 전달 → 마이크, 실제 통화 대신 물리적 오디오 루프백).

```bash
# 백그라운드에서 라이브 루프 시작
python -u live_transcribe.py --session live_test2 --model base --stt-interval 5 &

# 3초 뒤 잡담 재생
say -v Yuna "네 안녕하세요 여보세요"

# 3초 뒤 의료 관련 발화 재생
say -v Yuna "환자가 의식이 없어요 숨을 잘 못쉬어요"
```

### 실제 출력

```
[1차] 재변환 중... 누적 10.5초
[00:00:05.360] 네 안녕하세용 여보세요
  [0.306] 제외  네 안녕하세용 여보세요

[2차] 재변환 중... 누적 16.9초
[00:00:05.360] 네 안녕하세요 이어 보세요. 환자가 의식이 없어요. 춤을 잘 못 쉬어요.
  [0.627] 유지  네 안녕하세요 이어 보세요. 환자가 의식이 없어요. 춤을 잘 못 쉬어요.
```

**1차는 정확히 기대대로 동작했다** — 잡담("네 안녕하세요 여보세요")이
`score=0.306`으로 threshold(0.4) 미만이라 "제외" 판정을 받았다. 여기까지는
가이드 문서가 예상한 그대로다.

## 🔍 중요한 발견: 재변환 시 세그먼트 병합이 필터링 결과 자체를 오염시킬 수 있다

**2차 사이클에서 실제로 일어난 일**을 자세히 보면:

1. 2차 사이클은 버퍼 전체(0~16.9초)를 처음부터 다시 재변환한다.
2. 이번에는 VAD가 1차에서 두 문장으로 나눴던 구간을 **하나의 세그먼트로
   병합**해서 인식했다 — "네 안녕하세요 이어 보세요. 환자가 의식이
   없어요. 춤을 잘 못 쉬어요." (잡담 + 의료 발화가 한 덩어리).
3. 이 병합된 세그먼트의 `seg.end`가 1차의 `printed_until`보다 크므로
   `printed_until` 로직상 "새 턴"으로 판정되어 `all_turn_texts`에 **추가로**
   append되었다 — 원래 1차에서 이미 추가됐던 "네 안녕하세용 여보세요"
   턴은 그대로 남아있고, 그 옆에 병합된 버전이 하나 더 생겼다.
4. 이 병합된 턴을 필터에 넣으니, 잡담 부분이 의료 관련 문장(환자 의식
   없음, 호흡 곤란)과 한 텍스트로 묶여 있어 전체 유사도 점수가 **0.627로
   threshold를 넘어 "유지"** 판정을 받았다. **잡담 부분이 의료 발화에
   "묻어가서" 필터를 통과한 것**이다.

### 최종 텍스트 파일 상태

```bash
$ cat data/live_text/live_test2.txt
네 안녕하세용 여보세요 네 안녕하세요 이어 보세요. 환자가 의식이 없어요. 춤을 잘 못 쉬어요.
```

같은 잡담 문장이 사실상 두 번(원본 + 병합본) 들어가 있고, 최종 텍스트가
Step 5의 SBAR 구조화 입력으로 넘어간다면 다소 중복되고 부정확한 문맥이
LLM에 전달될 수 있음을 시사한다.

### 왜 발생하는가 (근본 원인)

Step 3 결과 문서에서 예고했던 "VAD 재판정으로 경계가 살짝 흔들려 드물게
한두 단어가 겹쳐 보일 수 있다"는 caveat이, 필터링 단계까지 오니 **단순
텍스트 중복을 넘어 분류 결과 자체가 달라지는 문제로 확장**된다는 것을
실제로 확인했다. `printed_until` 방식은 "세그먼트 경계가 사이클마다
안정적"이라는 암묵적 가정 위에 서 있는데, 재변환마다 whisper가 완전히
새로 세그먼트를 나누기 때문에 그 가정이 항상 성립하지는 않는다.

### 이번 단계에서 조치하지 않은 이유

가이드 문서(Step 3)가 이미 "완벽한 스트리밍 diff는 범위 밖"이라고 명시한
설계 결정과 일치한다. 이 프로젝트의 현재 목표는 "정직하게 동작하는 라이브
파이프라인을 눈으로 확인하는 것"이며, 세그먼트 병합/재분류로 인한 미세한
중복은 Step 5의 LLM 구조화 단계에서 어느 정도 자연스럽게 흡수될 가능성이
있다(LLM이 중복된 문장을 보고도 동일한 SBAR 요약을 만들어낼 수 있음 — 실제
Step 2 테스트에서 STT 오인식을 LLM이 문맥으로 보정한 사례와 유사한 패턴).
완벽한 해결은 Phase 3+의 "진짜 스트리밍 STT" 전환 시 근본적으로
해소될 문제로 남겨둔다.

## 📊 필터링 정확도 자체는 정상 동작

병합 이슈와 별개로, **필터가 텍스트 내용만으로 유사도를 판단하는 로직
자체는 정확했다**:

| 텍스트 | 점수 | 판정 | 평가 |
|---|---|---|---|
| "네 안녕하세용 여보세요" (순수 잡담) | 0.306 | 제외 | ✅ 정확 |
| "...(잡담)... 환자가 의식이 없어요. 춤을 잘 못 쉬어요." (혼합) | 0.627 | 유지 | ⚠️ 혼합 텍스트라 "유지"가 합리적이지만, 순수 잡담 부분만 따로 봤다면 제외됐어야 할 내용이 포함됨 |

threshold(0.4) 자체는 이번 테스트 샘플 기준으로 적절해 보인다 — 별도 조정
없이 기본값 유지.
